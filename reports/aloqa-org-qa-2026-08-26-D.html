Журнал аудита, владение workspace и подписи прав

Четыре находки по разделам Settings → Admin и Settings → Workspace. Главная: журнал аудита компании не показывает события уровня компании — изменения ролей и прав в него не попадают, хотя страница объявлена журналом компании, а сервер эти события пишет. Остальные три — тупик у владельца workspace, сырой ключ права в редакторе ролей и подзаголовок, обещающий несуществующие поля. Каждая находка подтверждена измерением и воспроизведена не менее двух раз.

Сборка: v0.61.0-rc.3.

Перепроверено на сборке v0.61.0-rc.4. Все четыре находки воспроизведены заново, ни одна не снята и ни одна не исправлена в промежутке. Исправлены две неточности в измерениях: в находке 1 — механизм (страница не запрашивает журнал компании; два запроса в первоначальном замере появились из-за самого пробника), в находке 3 — число прав в списке.

Highfrontend

[FE-WEB][ADMIN] Журнал аудита не показывает события уровня компании

Проблема

Владелец компании открывает Settings → Admin → Audit log, чтобы посмотреть, кто и когда менял роли и права. Страница подписана «A record of the administrative actions taken in this company», но выводит только события уровня workspace: создание, изменение и удаление ролей в таблицу не попадают никогда. Узнать, кто кому выдал полномочия, нельзя.

Как воспроизвести

  1. Войти владельцем компании.
  2. Открыть Settings → Roles, вкладка Company roles. Заполнить Role name, отметить любое право, нажать Create role.
  3. У созданной роли нажать Delete и подтвердить.
  4. Открыть Settings → Admin → Audit log.

Фактический результат

Ни создание, ни удаление роли в таблице не появляются. Если других административных действий в компании не было, страница показывает No audit entries found. Сервер эти события пишет, но страница за ними не обращается: при открытии она запрашивает только журнал workspace, а журнал компании не запрашивает вообще.

запросы к /api/v1/ при холодной загрузке страницы Audit log — 22, из них к audit-log:
  GET /api/v1/workspaces/{workspaceId}/admin/audit-log?limit=100    единственный
  журнал компании не запрашивается                                  ни разу

журнал компании  (11 записей): [company]   role.created / role.deleted, три пары
                               [workspace] invite.* и workspace.member_*
журнал workspace  (5 записей): только [workspace]
на экране         (5 строк):   те же пять строк журнала workspace
событий role.* на экране:      0

Фильтров на странице нет — только Export CSV, Export JSON и Previous / Next (неактивна: страница одна). Журнал workspace с явным scope_type=company отвечает 400:

GET /api/v1/workspaces/{workspaceId}/admin/audit-log?scope_type=company   400
GET /api/v1/companies/{companyId}/admin/audit-log?scope_type=company     200   3 записи

Новые события стоят в журнале компании первыми, так что пагинация их отсутствие не объясняет. Экспорт тоже не выручает: Export CSV и Export JSON выгружают тот же журнал workspace.

Ожидаемый результат

Журнал компании показывает и события уровня компании — создание, изменение и удаление ролей, выдачу и снятие прав, — а не только события текущего workspace.

Проверка

  • Создать роль компании и убедиться, что событие role.created появилось в таблице Audit log.
  • Открыть Audit log в компании, где были только действия с ролями, — таблица не пустая и No audit entries found. не показывается.
  • События уровня workspace (invite.created, workspace.member_removed) по-прежнему отображаются и не задваиваются.
  • Export CSV и Export JSON выгружают тот же набор событий, что показан в таблице.
Mediumfrontend

[FE-WEB][WORKSPACE] Владелец не может выйти из workspace: подсказка требует недоступной передачи владения

Проблема

Владелец workspace открывает Settings → Workspace → Danger zone, чтобы выйти из него. Кнопка Leave workspace неактивна, а подсказка требует сначала передать владение. Передачи владения в вебе нет, поэтому условие невыполнимо и выхода из состояния не существует.

Как воспроизвести

  1. Войти владельцем workspace.
  2. Открыть Settings → Workspace, блок Danger zone.
  3. Прочитать подсказку у неактивной кнопки Leave workspace и поискать передачу владения на обеих вкладках страницы и в Settings → Admin → Workspaces.

Фактический результат

Кнопка Leave workspace неактивна, подсказка — Transfer workspace ownership before leaving. Действия, передающего владение, на страницах нет.

Settings → Workspace, вкладка General — 21 элемент:
  17 пунктов навигации, General, Roles, Upload image, Leave workspace (disabled)
Settings → Workspace, вкладка Roles:
  Create role, Edit, Delete, Remove <роль> from <участник>
Settings → Admin → Workspaces — 21 элемент:
  Create workspace, Open …, Edit …, Show storage

совпадений transfer / ownership: 0

Перечислены все видимые button, a, [role=button] и select в области содержимого, а не прочитан текст страницы. В описании API также нет ни одного пути с transfer или owner.

Ожидаемый результат

Подсказка называет действие, которое пользователь может выполнить на этой же странице, и не отсылает к передаче владения, пока её нет в интерфейсе.

Проверка

  • Владелец открывает Danger zone и видит выполнимую инструкцию.
  • Обычный участник workspace по-прежнему может выполнить Leave workspace.
  • Текст подсказки согласован с ответом сервера на попытку выхода владельца.
Lowfrontend

[FE-WEB][ADMIN] В списке прав роли одно право подписано внутренним ключом audit.view

Проблема

Администратор создаёт роль и отмечает права. Все права перечислены понятными фразами, и только одно выведено служебным идентификатором audit.view — что именно он выдаёт, из подписи неясно.

Как воспроизвести

  1. Открыть Settings → Roles, вкладка Company roles.
  2. Посмотреть список под заголовком Permissions в форме создания роли.
  3. Повторить на вкладке Workspace roles.

Фактический результат

В обеих областях в списке присутствует строка audit.view вместо описания права.

Company roles (11 прав):
  … View company members / Remove members from the company /
  Bypass member privacy restrictions (DMs and invitations) /
  Manage your own privacy restrictions (DMs and invitations) /
  audit.view                        <- внутренний ключ
  All company permissions

Workspace roles (9 прав): audit.view между
  «Manage workspace roles and assign them to members» и «All workspace permissions»

Ожидаемый результат

Право подписано так же понятно, как соседние, — например «Просматривать журнал аудита».

Проверка

  • В Create role на вкладке Company roles право подписано фразой, а не ключом.
  • То же на вкладке Workspace roles.
  • Остальные подписи прав не изменились, All company permissions по-прежнему на месте.
Lowfrontend

[FE-WEB][WORKSPACE] Подзаголовок Workspace identity обещает поля URL и default channel, которых нет

Проблема

Пользователь открывает настройки workspace, чтобы изменить его адрес или канал по умолчанию. Подзаголовок блока обещает и то и другое, но в блоке есть только загрузка картинки и поле имени — искать остальное негде.

Как воспроизвести

  1. Открыть Settings → Workspace, вкладка General.
  2. Сравнить подпись блока Workspace identity с его содержимым.

Фактический результат

Подзаголовок — Name, URL, and default channel for this workspace., в блоке — аватар и одно поле Workspace name.

видимые поля ввода в области содержимого:
  1. Filter settings   (поиск по настройкам в боковой панели)
  2. Workspace name    (текстовое поле)
полей URL и выбора канала по умолчанию: нет

Ожидаемый результат

Подзаголовок описывает те поля, которые в блоке действительно есть.

Проверка

  • Подзаголовок Workspace identity перечисляет только присутствующие поля.
  • Если поля URL и default channel добавляются — они сохраняются и переживают reload.
  • Поле Workspace name по-прежнему сохраняется.
