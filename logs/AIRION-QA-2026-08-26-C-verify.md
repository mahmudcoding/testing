### Находка 5 [High] [frontend] — счётчик непрочитанного → **CONFIRMED и усилена**

Три прогона, все с записью строки сайдбара каждые 300 мс, начиная **до** сообщения bob:

```
прогон 1: 40 с   изменений aria-label нет,   все снимки visibilityState=visible
прогон 2: 259 снимков / 77,7 с   изменений нет,   все снимки visible
прогон 3: 175 снимков / 68,7 с   изменений нет
во всех трёх: anyUnreadLabelEverSeen = false
#qa-general НЕ приглушён: кнопка в шапке aria-label "Mute notifications", aria-pressed=false
после перезагрузки: aria-label "qa-general, 1 unread messages", текст "qa-general 1"
сервер знает правильный ответ: GET /workspaces/{ws}/unread →
  {"channel_id":"C4QCGENERAL0001","unread_count":1,"last_message_seq":21,"last_read_seq":20}
```

**Контроль, которого не было в оригинале — сокет в этой же вкладке жив.** Пока сайдбар стоял
мёртвым, bob написал в канал, который alice в этот момент СМОТРЕЛА:

```
t=28801 мс   openMsgs 6 → 7   сообщение "QA-VER-LIVE-CONTROL" доехало в открытый канал живьём
             и сайдбар в этот же момент ПЕРЕСТРОИЛСЯ (строки поменялись местами)
             — то есть компонент сайдбара не заморожен, он рендерится, просто без бейджа
```

**Граничная проверка — reload действительно необходим.** Оба перехода сделаны кликом,
без единой навигации (`performance.getEntriesByType('navigation').length` = 1 до и после):

```
клик по строке уже открытого канала в сайдбаре → rows: "qa-general" (бейджа нет)
клик по ссылке раздела, переход на /w/{ws}/chat/mentions, sameDocument=true → бейджа нет
полная перезагрузка → "qa-general, 1 unread messages"
```

**Корневая причина, замер WebSocket.** Обёртка на `window.WebSocket` (init-script + reload),
пишет обе стороны:

```
сокет: wss://airion-cargo.store/ws/chat?resume_key=…&token=…
клиент ОТПРАВИЛ за всю сессию ровно две подписки:
  {"type":"subscribe","channel_id":"C4QCPRIVATE0001"}     ← открытый канал
  {"type":"subscribe","channel_id":"C4OVEWOTJW1AA86"}     ← DM
  подписки на #qa-general (C4QCGENERAL0001) нет, workspace-wide подписки нет
клиент ПОЛУЧИЛ, пока bob писал в #qa-general:
  {"channel_id":"C4QCPRIVATE0001","type":"subscribed"}
  {"channel_id":"C4OVEWOTJW1AA86","type":"subscribed"}
  {"channel_id":"C4QCPRIVATE0001","last_read_seq":7,"type":"channel_read"}
  {"channel_id":"C4QCPRIVATE0001","last_read_seq":7,"type":"channel_read_receipt",...}
  {"type":"pong"}
  кадров про новое сообщение в #qa-general: 0
```

Вывод: клиент подписывается только на открытый канал (и DM), поэтому сервер про активность
в остальных каналах ему ничего и не шлёт — обновлять бейдж нечем до полной загрузки, которая
перезапрашивает `/workspaces/{ws}/unread`. Метка `[frontend]` в отчёте **верна** и теперь
подтверждена замером, а не выведена по аналогии.

Это же окончательно закрывает вопрос про [ALK-2905] (`у приглушённого канала unread badge
не обновляется в реальном времени`): причина не в mute-фильтре на применении апдейта —
апдейт не приходит вовсе, ни для приглушённого канала, ни для обычного. Формулировка
отчёта («исправление, ограниченное приглушёнными каналами, эту проблему не закроет») верна;
в измерительный блок добавлены строки про подписки.

## Заметки по ригу (не про продукт)

- В прогоне 3 `allVisible` вернул false: часть снимков со `visibilityState != visible`.
  Причина — рижная: окна alice и bob развёрнуты на весь экран, и запуск драйвера в окне bob
